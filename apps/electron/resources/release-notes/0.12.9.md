# v0.12.9 — Durable autonomous execution and current provider models

## Features

- **Current OpenAI models** — Add GPT-6.1 Sol, GPT-6 Sol and GPT-6 Luna to OpenAI API and eligible ChatGPT/Codex connections, with provider-compatible reasoning and request serialization.
- **YOLO execution** — Execute mode with external actions enabled continues authorized work without permission, plan or clarification handoffs. Missing credentials, essential facts or exhausted recovery produce an explicit incomplete result instead of a false success.

## Improvements

- **Durable objectives and receipts** — Persist objective authority, provider dispatch and tool observations so an interrupted turn can reconcile existing work before retrying an external effect.
- **Verified completion** — Check acceptance criteria against host-owned observations and expose the current evidence context to the agent. Coordination messages and results from unrelated chats cannot prove completion.
- **Selected-model continuity** — Preserve the selected provider, model and reasoning through auxiliary queries, delegated work and bounded recovery. Unavailable selections fail explicitly.

## Bug Fixes

- **Conversation questions** — Keep answered and cancelled questions beside their original messages instead of accumulating them at the bottom. Pending questions remain reachable, and read-only transcripts preserve the same chronology.
- **Interrupted tool results** — Preserve executed tool identities and reconcile returned results after a runtime interruption, including Pi Bash-to-Read normalization.
- **Permission consistency** — Carry the user's recorded execution authority through resumed turns while retaining the separate Explore and Ask modes.
- **Installer verification** — Check bundle provenance, backup integrity, profile preservation and the running application identity before accepting a local staging replacement.

## Validation limits

- New model availability depends on the provider account. The pinned runtime uses its validated context and reasoning limits.
- Verified test journeys do not establish universal success on arbitrary long-running tasks or validate the completion of an existing CRM/email campaign.
